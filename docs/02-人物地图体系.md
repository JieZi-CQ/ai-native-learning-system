# 2️⃣ 如何建立你的"全球开源社区人物地图"？

这不是一份"大佬名单"，而是一个**可持续更新的、分类清晰的、可验证的人物数据库**。

## 分类维度（多个角度理解一个人）

### 维度 1：开源历史坐标

这决定了一个人的"基因"：

**第一代开源先驱**（1990s-2000s）
- Linux 之父 Linus Torvalds
- GCC、GNU 的贡献者
- Apache 基金会的早期成员
- 代表：稳定、经历了真实的大规模应用考验

**第二代开源浪潮**（2000s-2010s）
- Python、Ruby 社区的核心人物
- Git、GitHub 时代的弄潮儿
- 开源数据库（MySQL、PostgreSQL）的维护者
- 代表：见证了开源从"理想"到"商业化"的过程

**第三代互联网规模**（2010s-2015）
- Docker、Kubernetes、云原生的创造者
- Node.js、Go 语言的传播者
- 大数据框架（Spark、Hadoop）的贡献者
- 代表：处理过真实的百万级规模问题

**第四代 AI 时代**（2015-至今）
- TensorFlow、PyTorch 的核心贡献者
- Hugging Face、OpenAI 的开源推手
- LLM 应用框架的创造者（LangChain 等）
- 代表：在 AI Native 时代的新问题上有深度

### 维度 2：当前角色

- **活跃的开源维护者**：正在维护 1-3 个活跃项目，定期 Review PR、回复 Issue，每周有新的代码提交

- **独立开发者/创意人**：创造了某个有趣的项目但不一定大规模维护，可能因为要做其他事而不频繁更新，但代表了某种技术思路或产品理念

- **企业的开源推手**：代表公司维护开源项目，有资源支持，但受公司战略影响

- **学术研究者转型**：从论文到代码实现，可能不重视工程实践，但创新能力强

- **产品经理/创业者**：既有技术背景也有产品思维，他们的项目通常"易用性"很强

- **已功成身退但历史重要**：不再活跃但对某个领域有深远影响，值得学习他们的思想，但不用实时关注

### 维度 3：技术领域

- 基础设施（Linux、Kubernetes、数据库）
- Web 全栈（框架、前端、后端）
- AI/LLM（模型、框架、应用）
- DevOps/工具链（Docker、CI/CD、监控）
- 开发者工具（编辑器、包管理、构建工具）
- 安全（密码学、审计、渗透）

### 维度 4：地域背景

- 全球知名（美国、欧洲主导）
- 华人社区（大陆、台湾、海外）
- 区域代表（如：印度的开源贡献者）

### 维度 5：活跃程度

用数据衡量：
- **非常活跃**：最近 1 周有 Commit 或 Review
- **活跃**：最近 1 个月有活动
- **偶尔活动**：最近 3 个月有活动
- **维持状态**：项目存在但不频繁更新
- **已停更**：最后一次活动超过 1 年

## 如何具体建立这个地图

### 第一步：从里程碑项目扫描

从这些项目入手，识别核心贡献者：

**基础设施**
- torvalds/linux
- kubernetes/kubernetes
- containerd/containerd

**Web/编程语言**
- python/cpython
- tensorflow/tensorflow
- pallets/flask

**数据库**
- postgres/postgres
- mongodb/mongo
- tikv/tikv

**AI/LLM**
- huggingface/transformers
- langchain-ai/langchain
- mistralai/mistral-src

**开源组织**
- CNCF Projects
- Apache Projects
- Linux Foundation Projects

对每个项目，提取：
- Top Committers（过去 1 年）
- Core Maintainers（当前）
- 活跃的 Code Reviewers
- 他们各自维护的其他项目

### 第二步：建立关联网络

```
Person A 维护了项目 X
         ↓
Project X 的 Contributors 中有 Person B
         ↓
Person B 的主要项目是 Project Y
         ↓
Project Y 和 Project Z 在 GitHub 中有讨论
         ↓
发现隐形的重要人物和技术生态
```

### 第三步：追踪他们的当前动态

对每个重要人物：

- GitHub 个人资料（最近 Star/Watch 的项目）
- 最近的 Commit 活动
- 是否有个人博客/推特
- 现在工作的公司
- 最近参与的讨论（GitHub Issues/Discussions）

### 第四步：纳入华人社区

**组织层面**
- 国内科技公司的开源部门
  - 阿里：Dubbo、SOFA、Seata
  - 字节：ByteDance 开源
  - 腾讯：TencentOS、Tars
  - PingCAP：TiDB
  - 小红书：可观测性项目
  - 快手：推荐系统开源

- Apache 基金会中的中文贡献者
- Linux 基金会中的中国代表

**个人层面**
- 在中文社区活跃的开源贡献者
  - Gitee 上的高星项目维护者
  - 知乎/掘金的技术大V
  - 微博上的技术意见领袖

**社区层面**
- OpenAtom（开放原子开源基金会）
- 中国开源推进联盟
- 各地的开源社区（Beijing、Shanghai、Hangzhou）

## 如何验证人物价值（不只看 Stars）

对于任何一个"据说很厉害"的人物，需要核实：

### 第一级数据：GitHub 指标
- 这个人维护了多少项目？
- 这些项目各有多少 Star？
- 最近一个月有没有活动？
- 维护的项目是否健康（Issue 回复快不快）

### 第二级数据：项目影响力
- 他的项目被引用了多少次？
  - 用 GitHub Search：`references:owner/repo`
- 被哪些"大项目"依赖？
  - TensorFlow、Kubernetes 等级别的大项目
- 真实用户数量是多少？
  - 看项目的 Discussions、Issues 中的真实问题

### 第三级数据：代码质量
- Code Review 的深度和严谨程度
- 测试覆盖率
- 文档的完善程度
- 是否有明确的技术决策记录（ADR）

### 第四级数据：社区评价
- GitHub Issues/Discussions 中的讨论
- Reddit/HN 上关于他的项目的评论
- 是否解决了真实问题（不是 over-engineered）
- Contributor 的评价（他好相处吗）

### 第五级数据：长期贡献
- 这个人维护项目多久了？
- 是否有过"项目停更"的历史？
- 最近 3 年的技术方向是否一致？
- 是否在积极拥抱新技术（而不是固守老框架）

### 第六级数据：教育贡献
- 是否写过高质量的技术文章？
- 是否在会议上演讲？
- 是否维护了教学项目或教程？
- 社区中对他的教学能力的评价？

## 人物数据库模板

为每个重要人物建立这样的记录：

```
人物：Guido van Rossum (Python 之父)

基本信息：
- GitHub：guido
- 现在在：Microsoft
- 主要贡献：CPython 核心维护者

历史贡献：
- Python 语言设计（1989-2021 年任 BDFL）
- PEP 流程的建立
- Type Hints 的推进

当前活动：
- 不再是 CPython 的 BDFL（2019 年退休）
- 偶尔参与重要决策讨论
- 在 Python Steering Council 中有席位

项目成果：
- Python（200M+ 下载/月）
- 被 TensorFlow、Django、Pandas 等依赖

学习价值：
- 如何设计易用的编程语言
- 如何管理大规模开源社区
- 长期的技术品味和决策

值得看的内容：
- PEP 系列（特别是 PEP 20 Zen of Python）
- 他在 PyCon 的演讲
- CPython 的 Issue 讨论

当前值得关注程度：
- 对新技术方向：中等（已退休）
- 对学习编程理念：高（永远有价值）
```

## 定期维护建议

- **每月一次**：检查关注人物的最新活动
- **每季一次**：评估新发现的重要人物是否应该纳入
- **每半年一次**：回顾整个人物地图，是否需要分类调整
- **每年一次**：大评估，看谁已经失去活跃度，谁新兴崛起
